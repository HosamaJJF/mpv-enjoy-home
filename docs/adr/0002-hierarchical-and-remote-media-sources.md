# ADR 0002：分层媒体库与 Emby/Jellyfin 媒体源

- 状态：Accepted
- 日期：2026-08-03
- 更新：2026-08-09

## 背景

把扫描出的每个视频文件直接放在媒体库顶层，会让剧集目录迅速变得不可浏览。固定的摄像机
占位图没有提供信息，也掩盖了应用尚未生成本地缩略图的事实。同时，产品定位需要覆盖已有
Emby/Jellyfin 媒体库，而不是局限于本地文件。

## 决策

1. 本地扫描继续只索引用户显式添加目录中的普通媒体文件，但为每个条目保存相对路径。
   浏览 API 根据相对路径即时生成“文件夹或视频”条目，UI 逐级展开。首页最近更新改为展示
   具体本地文件，并与各远程服务器按 `DateCreated` 返回的电影、单集和视频合并排序；远程
   单集以所属剧集作为详情目标。单个服务器失败时跳过该批结果，不影响其他首页条目。
2. 没有真实缩略图时不渲染缩略图容器。Emby/Jellyfin 的 Primary Image 由 Rust 后端使用
   认证请求头获取，限制响应大小后传给 UI；本地条目在引入受控的缩略图生成器前使用无图
   列表布局。远程条目同时传递 `PrimaryImageAspectRatio`，媒体库和单集采用横版卡片，剧集
   海报保持竖版。网格以最小卡片宽度为换列阈值，用 `auto-fit` 和弹性列填满当前行；窗口继续
   变宽至能容纳新列时，卡片缩回较小宽度并增加列数。
3. 新增 `media_servers` 表和窄化的远程媒体接口。Emby 与 Jellyfin 使用共同的兼容端点：
   `Users/{UserId}/Views`、`Users/{UserId}/Items`、`Items/{Id}/Images/Primary` 和
   `Videos/{Id}/stream`。Emby 适配器在标准服务器地址后加入 `/emby`，Jellyfin 保留用户
   配置的 Base URL。
4. 保存后，访问令牌只由 Rust 后端读取，不进入返回给 WebView 的 DTO。浏览与封面请求通过
   `X-Emby-Token` 请求头认证；播放 URL 在 Rust 内追加同源 `api_key` 后直接交给 mpv，使
   外挂轨道和读取当前网络媒体的 mpv 脚本无需复现私有请求头。播放器仍使用参数数组且不经过
   shell。
5. 首版远程播放只支持 Direct Play。转码协商留给后续独立决策；播放会话与进度同步由
   [ADR 0003](0003-private-mpv-ipc-playback-progress.md) 补充。
6. 连接服务器只接受用户名/密码，由 Rust 发送至 `Users/AuthenticateByName`；Access Token 和
   密码保存在 Rust 可访问的 SQLite 中，不向 WebView 返回，也不使用系统钥匙串。请求同时携带
   `Authorization` 与 `X-Emby-Authorization` 客户端标识，以兼容 Emby/Jellyfin 版本差异。
   `DeviceId` 使用安装级随机标识并持久化，不能由所有安装共享一个硬编码值。
   后续请求返回 401 时视为当前令牌已失效，后端以同一服务器为粒度收敛并发请求，使用保存的密码
   自动重新认证一次；验证成功后在同一条数据库记录中替换令牌和用户会话信息并继续原请求。
   没有保存密码或自动认证失败时，UI 才打开原连接的重新登录表单。403 继续表示用户权限不足。
7. 播放本地视频时，只把数据库中同目录的已索引视频按自然顺序交给 mpv，并用
   `--playlist-start` 定位用户选择的条目；`sub-auto=exact` 和 `audio-file-auto=exact` 负责
   加载同名外挂轨道。播放远程单集时，通过 `SeriesId` 取得按季/集排序的播放列表，并从
   `MediaSources` 提取每个条目的外部字幕和外部音轨流；经同源与协议校验的远程 URL 使用
   mpv 的 `--{` / `--}` per-file 参数组绑定各自的外挂轨道，并以
   `剧集名 SxxExx - 单集名` 设置 `force-media-title`。不再使用 `autoload-files=no`，因为该
   选项会使显式加入的外挂轨道不被自动选择。本地媒体列表前保留 `--`，所有播放请求均使用
   参数数组，不经过 shell。

## 后果

- 本地数据库 schema v2 增加媒体相对路径，v3 为已有服务器增加可空密码字段；旧媒体行的
  相对路径在浏览时由绝对路径回算，并会在下次扫描时写入，旧服务器首次仍需手动重新登录。
- 远程浏览依赖用户显式提供的服务器地址与登录凭据，会产生用户请求的局域网或互联网访问；
  应用本身不增加任何遥测或自动发现。
- 媒体库使用独立来源选择页进入本地目录或服务器内容，不再依赖可能在窄窗口裁切的横向来源栏。
- 将锁文件中已有的 `chrono` 0.4.45 提升为直接依赖，仅用于把服务器 RFC 3339 `DateCreated`
  转为统一时间戳；该 crate 采用 MIT/Apache-2.0 双许可证，不增加新的传递依赖。
- 令牌和密码保存在平台应用数据目录的 SQLite 数据库中；密码不经过额外的应用层加密，安全边界
  依赖当前系统用户的应用数据权限，Unix 平台额外把目录收紧为 `0700`，数据库及 WAL/SHM
  文件收紧为 `0600`。
  UI DTO 继续不暴露令牌或密码，日志和错误消息也不得包含它们。
- 从旧版硬编码 `DeviceId` 升级时，已有令牌若被服务器绑定到旧标识，可能需要执行一次重新登录；
  新的安装级标识保存后会在后续启动中保持不变。
- 远程播放的认证令牌当前位于 mpv 命令行中的同源媒体 URL；同一系统用户的进程检查工具及
  mpv 脚本可能看到该参数。未来可用仅限当前用户的短生命周期本地代理进一步收紧令牌暴露面。
- 本地缩略图生成需要一个可跨三个目标平台验证、不会修改媒体文件的新基础设施适配器；在
  此之前，无图列表比伪装成缩略图的固定图标更诚实也更紧凑。
