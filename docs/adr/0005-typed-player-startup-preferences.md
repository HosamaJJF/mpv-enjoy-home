# ADR 0005：类型化播放器启动偏好与可选脚本协作

- 状态：Accepted
- 日期：2026-08-09
- 更新：2026-08-11（增加 uosc_danmaku 样式覆盖）

## 背景

外部 mpv 会读取自己的配置文件，但修改默认音量、全屏状态或脚本状态通常要求用户查找并编辑
平台相关文件。Home 可以为自己发起的播放提供少量常用覆盖项，但不能因此开放任意命令行、
改写用户配置或把某个 mpv 发行版的目录布局带入 UI。

mpv 的启动音量和全屏状态可以直接用全局选项覆盖。uosc_danmaku 的实际显示开关则由脚本消息
切换，并通过 `user-data/uosc_danmaku/danmaku-switch-on` 暴露状态，不等同于插件的
`auto_load` 配置项。

uosc_danmaku 的样式选项可以在启动时通过带脚本标识前缀的 `script-opts` 传入。这样可以只影响
Home 发起的播放器进程，并保留用户配置文件作为未覆盖字段的事实来源，无需依赖插件内部的运行时
样式菜单消息。

## 决策

1. 新增窄化的 `PlayerPreferences` DTO，保存可选启动音量、uosc_danmaku 样式以及全屏、弹幕的
   `inherit/on/off` 三态。样式字段默认不覆盖，升级不改变现有 mpv 行为。
2. 启动音量只接受 0 到 100。音量与全屏选项由 Rust 生成并放在媒体参数之前；UI 不接受任意
   mpv 参数文本。
3. 偏好保存在通用 `settings` 表的独立 JSON 值中，不修改数据库 schema，也不写入 mpv 配置。
4. 远程播放复用已有私有随机 IPC；本地播放只在弹幕状态不是 `inherit` 时创建相同安全属性的
   IPC。媒体加载后读取 uosc_danmaku 状态，仅在与期望不同时发送一次定向脚本消息。
5. 插件缺失、属性不可用、脚本消息失败或 IPC 创建失败都只让弹幕偏好失效，不阻止播放器启动。
   远程进度回传同样在 IPC 创建失败时降级，而不是阻塞 Direct Play。
6. 弹幕样式只开放插件样式菜单已有的粗体、字号、描边、阴影、滚动时长、不透明度和显示区域。
   Rust 对每项执行范围或枚举校验，并为明确设置的字段逐项生成
   `--script-opts-append=uosc_danmaku-<option>=<value>`；样式不创建或使用 IPC。

## 后果

- 用户可以在不编辑配置文件的情况下控制 Home 发起播放时的音量、全屏、弹幕初始状态和样式。
- 用户原有 mpv 配置仍是默认事实来源，只有明确选择的字段才会被覆盖。
- uosc_danmaku 保持可选依赖；项目不安装、更新或修改插件文件，其他播放器脚本不受影响。
- 本地播放在需要同步弹幕状态时增加一个短生命周期后台监控线程和私有 IPC，线程不阻塞 Tauri
  命令，播放器退出后清理端点。
