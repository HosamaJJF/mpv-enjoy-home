# ADR 0006：经过验证的 Release 更新边界

- 状态：Accepted
- 日期：2026-08-15

## 背景

应用需要让普通用户发现并取得新版本，但更新包最终会被打开或执行，安全级别高于普通内容请求。
如果 WebView 可以提供下载 URL、文件名或任意外链，受损的前端上下文就可能把 Rust 后端变成
任意文件写入或进程启动入口。通过路径和文件名模糊匹配发行版、平台或安装类型，也可能下载错误
架构的包或在 MSI、NSIS、免安装版之间错误切换。运行中的 Windows 便携程序自行覆盖自身还会
产生无回滚的半更新状态。

## 决策

1. 更新 UI 只发送无参数的检查、下载当前匹配包和打开项目 Release 页面命令。仓库、附件名、
   下载 URL、digest、临时路径和启动方式都由 Rust 决定；删除通用外链命令。
2. 默认更新源固定为 Home 仓库。其他发行版必须在编译时一次性提供
   `MPV_ENJOY_HOME_UPDATE_REPOSITORY`、`MPV_ENJOY_HOME_UPDATE_ASSET_PREFIX`、
   `MPV_ENJOY_HOME_DISTRIBUTION_NAME`、`MPV_ENJOY_HOME_DISTRIBUTION_VERSION` 和
   `MPV_ENJOY_HOME_PORTABLE_MARKER`；配置缺项直接报错，不再检查父目录名或硬编码播放器布局。
   只有调试构建可用 `MPV_ENJOY_UPDATE_URL` 指向回环 HTTP 测试服务，并可用
   `MPV_ENJOY_FORCE_CURRENT_VERSION` 构造升级场景。
3. 最新标签和当前版本必须是有效 SemVer。每个平台、架构和安装类型只允许一个精确附件名，不
   使用扩展名兜底。下载 URL 必须精确属于配置仓库和标签，元数据与文件均有大小上限；文件必须
   与 GitHub Release API 返回的 `sha256` digest 和声明大小一致后才能打开。临时文件使用随机、
   当前用户私有目录和排他创建，中途失败即删除。
4. macOS 打开验证后的 DMG；带明确便携标记的 Windows 副本下载并定位验证后的 ZIP，用户退出
   后手动覆盖；带 `uninstall.exe` 的 NSIS 副本可以启动验证后的 setup。无法确认安装器类型时
   只引导用户前往 Release。删除便携版自动重命名、覆盖、重启以及启动时清扫可执行目录内
   `.old`/`.pending_delete` 文件的逻辑。
5. Windows 便携 ZIP 与 CI 测试 ZIP 都包含 `.mpv-enjoy-home-portable`。集成发行版使用自己在
   编译元数据中声明的标记，并负责在其便携包中注入同名文件。

## 依赖与许可证

- `semver` 1.0.28 用于严格版本解析，采用 MIT/Apache-2.0 双许可证。
- `sha2` 0.10.9 用于流式 SHA-256 校验，采用 MIT/Apache-2.0 双许可证。
- 两项原本已在锁文件依赖图中，本项目将其提升为精确版本的直接依赖；移除不再需要的 `zip`
  直接依赖及其只由该路径引入的传递依赖。

## 后果

- 前端失去通用下载和打开外链能力，Release API 被攻破或仓库维护者凭据失陷仍属于信任边界，
  但网络中间人、错误附件选择和前端参数注入不能绕过后端校验。
- 便携版更新多一步人工退出和解压，但不会在运行中留下不可恢复的半覆盖状态。
- v1.0.3 及更早的 Home 免安装 ZIP 没有便携标记，首次升级到包含本决策的版本时会被视为未知
  安装类型，需要从 Release 手动下载；解压新 ZIP 后，后续版本即可可靠识别。
- MSI 和其他未知安装方式暂不自动执行更新；后续只有在能可靠识别并完成三平台升级回归后，
  才能增加新的类型化安装动作。
- 正式发布除了构建验证，还必须做从上一版本到候选版本的真实更新检查、下载、digest 校验和
  打开/定位行为回归。
