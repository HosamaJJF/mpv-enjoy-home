# ADR 0004：远程元数据视图与统一媒体详情页

- 状态：Accepted
- 日期：2026-08-04
- 更新：2026-08-11

## 背景

按 `ParentId` 逐层展示 Emby/Jellyfin 返回的所有文件夹，会把服务器的物理目录暴露给用户。
电影因此常出现“文件夹 → 同名电影”的重复点击；剧集也必须先打开只有一个条目的季度页。
这种文件浏览器模型还无法在播放前同时展示作品简介、用户进度和演职人员。

## 决策

1. `Users/{UserId}/Views` 仍是远程顶层，每个条目代表用户有权限访问的媒体库。
2. 进入媒体库时，Rust 先读取媒体库的 `CollectionType`，再使用 `ParentId`、
   `Recursive=true` 与 `IncludeItemTypes` 查询 `Movie`、`Series` 或 `Video`。普通物理
   `Folder` 不作为库内一级条目返回，界面名称以服务器媒体元数据为准。
3. `Series`、`Movie` 和 `Video` 都是详情目标，不再因为 `Series.IsFolder=true` 被视为导航
   容器。只有真正的 `CollectionFolder`、`Folder` 和 `BoxSet` 使用集合导航语义。
4. 新增窄化的 `RemoteMediaDetail` DTO。单项详情包含系列或电影简介、标签、年份、时长、
   评分、用户播放状态、Primary/Backdrop 图片标识、人员和媒体源。剧集详情额外一次查询全部
   `Season` 与 `Episode`，并按季号、集号排序。
5. 季不是独立页面，而是详情页中的筛选状态。只有一季时不显示无意义的筛选控件，但仍展示
   季封面和季简介，与页面上方的系列简介同时保留；多季时选择季只筛选同页单集。
6. 电影和普通视频只有一个可播放条目，详情页只提供播放或继续播放入口，随后展示演职人员。
   剧集的单集卡片展示各自简介、时长、观看状态和进度。详情页不展示冗长的媒体文件和轨道表；
   播放阶段仍会在 Rust 内按需读取 `MediaSources`，供 mpv 直播放和外挂轨道使用。
7. 图片命令只接受 `Primary` 与 `Backdrop` 两类，并限制宽度和响应大小。Backdrop 必须使用
   索引 0；UI 只根据 DTO 中的图片标识请求图片，不自行拼接远程 URL 或持有访问令牌。
8. 远程浏览列表可以按自然名称或 `DateCreated` 升降序排列。顶层媒体库的时间由库内最新的
   电影、单集或视频聚合得到，不使用媒体库容器本身的时间；剧集时间按 `SeriesId` 聚合为其
   最新一集的添加时间，不使用系列自身的创建时间。排序控件不进入剧集详情页，季与集继续严格
   按 `IndexNumber`、`ParentIndexNumber` 排列。

## 后果

- 电影与单季剧集减少一次或多次无信息价值的点击，远程导航由文件系统结构转为媒体语义。
- 一个剧集详情请求会额外读取季和最多 2000 个单集；当前不做远程元数据缓存。大型媒体库后续
  可在保持 DTO 语义不变的前提下加入分页或缓存。
- 详情页获得更多服务器元数据，但对缺失封面、季简介、人员照片和流字段必须提供无图或文字
  回退，不能把字段缺失当成整个页面失败。
- BoxSet 仍保留集合导航；其专用聚合详情不在本决策范围内。
- 读取服务器顶层媒体库时，每个可见媒体库会增加一次只取一个条目且不取图片的轻量查询，用于
  得到库内更新时间；媒体库数量通常远小于媒体条目数量，后续可在不改变 DTO 的情况下并发或缓存。
- 读取含剧集的媒体库时，会额外按添加时间倒序分页读取不含图片的单集 ID、`SeriesId` 与
  `DateCreated`，收集到每个当前剧集的最新一集后立即停止；单次最多检查 100,000 个单集。
